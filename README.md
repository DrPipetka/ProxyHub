# ProxyHub

Локальный менеджер конфигов VLESS, VMess, Shadowsocks, Trojan и Hysteria2 на Python 3.11+, FastAPI, SQLite WAL и xray-core. Принимает подписки и списки, проверяет качество, поддерживает свободный пул SOCKS5 и выдаёт прокси в аренду через API. Русский веб-интерфейс работает без CDN и npm-сборки: HTML, локальный htmx и JavaScript.

## Быстрый запуск

**Windows:** установите Python 3.11 или новее с python.org и запустите `run.bat`. При первом запуске скрипт создаст `.venv` и установит зафиксированные зависимости.

**Linux:** `sh run.sh`. Нужен Python 3.11+ с модулем `venv`. В стандартной Ubuntu 22.04 обычно установлен Python 3.10: сначала установите Python 3.11+ и соответствующий пакет `venv`, либо создайте окружение командой `python3.11 -m venv .venv`.

Ручной запуск из корня проекта:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.venv\Scripts\python.exe -m proxyhub
```

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
.venv/bin/python -m proxyhub
```

Откройте **http://127.0.0.1:8080**. При первой локальной установке пароль пустой: нажмите «Войти», затем задайте пароль в «Настройках». Сгенерированный API-токен доступен там же через кнопку копирования. Перезапуск сохраняет токен, настройки и конфиги. Для остановки используйте **Ctrl+C** в терминале.

Первый запуск автоматически скачивает официальный xray-core из GitHub Releases в `./bin`, проверяет SHA256 из файла `.dgst`, затем скачивает DB-IP Country Lite. Инициализация идёт в фоне; интерфейс доступен сразу. Ошибки загрузки видны в журнале, повтор происходит через 30 секунд. После загрузки всех ресурсов интернет нужен только для подписок и проверки прокси. Можно заранее задать собственные пути к бинарнику и MMDB, отключив `auto_download`.

Windows Defender/антивирус может проверять или блокировать скачанный сетевой бинарник. Не отключайте защиту; проверяйте источник, контрольную сумму и разрешения конкретного файла. Для Windows ARM64 и Linux ARM64 установщик выбирает соответствующую сборку, но эти платформы требуют отдельной проверки на устройстве.

## Первый импорт

1. Откройте «Добавить конфиги».
2. Вставьте ссылки, загрузите текстовый файл или укажите URL подписки. При заполненном URL содержимое текстового поля не используется.
3. При необходимости задайте метку источника.
4. После импорта перейдите во «Все конфиги»: там видны ошибки разбора и причины неподдерживаемых параметров.
5. Валидные конфиги автоматически пополняют пул. Без рабочих пользовательских конфигов пул остаётся пустым.

Поддерживаются ссылки `vless://`, `vmess://` (base64 JSON), `ss://` (SIP002 и legacy base64), `trojan://`, `hysteria2://`/`hy2://`, `tuic://`; обычные и base64-подписки; Clash YAML с `proxies`; sing-box JSON с `outbounds`. Исходный конфиг сохраняется. Хеш не учитывает имя, но учитывает протокол, адрес, порт, учётные данные и транспорт.

TUIC разбирается и сохраняется как `unsupported`: второй адаптер sing-box не входит в эту версию. Hysteria2 доступна только если установленный xray проходит пробу генератора. Поддерживаются транспорты TCP/RAW, WS, gRPC, HTTPUpgrade, XHTTP, Hysteria; TLS и REALITY. Неизвестные параметры ссылки, неподдерживаемые транспорты, плагины Shadowsocks и обфускация Hysteria получают явную причину `unsupported`. Приложение не обещает поддержку всех расширений Clash/sing-box. Вспомогательные outbounds без сервера сохраняются как ошибка разбора, а не превращаются в прокси.

## Проверки, пул и аренда

- Планировщик выбирает ограниченные пачки SQL-запросами по индексам. Приоритет: ручная проверка → поднятые/арендованные → новые → валидные → невалидные после паузы.
- Один временный процесс xray обслуживает пачку (25 по умолчанию), каждому конфигу выделяется свой SOCKS5-порт. Общая конкурентность — 50.
- Дешёвый этап: успешный HTTP-ответ, прогрев и медиана пинга, выходной IP, страна MMDB, утечка прямого IP, при необходимости реальный DNS-запрос через SOCKS5 UDP ASSOCIATE. Дорогой этап скачивания выполняется после порогов и проверки дубля IP. Скорость — десятичные Мбит/с, объём — десятичные МБ.
- При выключенном измерении его запросы и критерии не выполняются. Для базовой проверки доступности HTTP используется список `ping_urls` даже при выключенном замере пинга.
- Полный отказ тестовой группы URL в пачке вместе с неудачной прямой пробой откладывает проверку на 60 секунд и не увеличивает счётчик неудач. Недоступность MMDB/прямого IP при включённом соответствующем критерии также считается ошибкой теста.
- `pool_size` — число **свободных** поднятых SOCKS5. Арендованные идут сверх него, до заполнения диапазона портов. Пул работает в одном процессе; штатные CLI-команды xray `api adi/ado/rmi/rmo/adrules` обращаются к его локальному gRPC API HandlerService/RoutingService.
- По умолчанию обычное добавление при ошибке API не перезапускает весь пул. Флаг `pool_restart_fallback` разрешает этот резервный способ. При невозможности удалить inbound приложение аварийно перезапускает пул даже без флага: нельзя оставить незарегистрированный доступный SOCKS5. Существующие TCP-соединения при таком аварийном восстановлении прерываются; событие записывается в журнал.
- Выдача сериализована общей асинхронной блокировкой вместе с изменением состояния и выделением порта. Один конфиг не может быть выдан двум клиентам. Во время перепроверки поднятый конфиг сохраняет состояние аренды, но временно исключён из кандидатов выдачи.
- `used` и TTL закрывают SOCKS5 и отправляют конфиг в отлежку. После неё по умолчанию выполняется повторная проверка. `release` возвращает конфиг без отлежки.
- Провал активной проверки обрывает аренду с `lease_status=broken`. Успех обнуляет последовательные неудачи. Ручная перепроверка обходит паузу и blacklist, но не может сделать неподдерживаемый протокол поддерживаемым.
- Первый прошедший проверку выходного IP становится мастером. После его отказа, отключения, удаления или смены выходного IP дубли проверяются заново.

## Подписки и расписание

При импорте URL подписка сохраняется с интервалом обновления (по умолчанию 60 минут; 0 — только вручную). Во вкладке «Подписки» доступны изменение интервала, ручное обновление, удаление расписания, последнее успешное обновление, следующая попытка, длительность и ошибки. Интервал отсчитывается от завершения попытки, включая неудачную; расписание переживает перезапуск, просроченные подписки обновляются после запуска приложения. Старые разовые импорты не содержат URL подписки — для включения расписания добавьте их URL повторно.

Для массовой загрузки вставьте ссылки в поле **«URL подписок»** (по одной на строку) или выберите TXT через **«Загрузить список подписок»**. До 500 ссылок за раз; источник и интервал общие. Пустые строки игнорируются, повторяющиеся URL загружаются один раз. Ошибка отдельной подписки не останавливает остальные; итог содержит общие счётчики и результат для каждой ссылки. Недоступные подписки сохраняются для повторного обновления по расписанию.

Для GitHub указывайте ссылку на конкретный файл подписки: `https://github.com/owner/repo/blob/main/server.txt` или Raw URL. Ссылки `blob` и `raw` автоматически скачиваются с `raw.githubusercontent.com`. Ссылки на репозиторий или папку отклоняются. HTML-страницы не сохраняются как конфиги. Ошибочные строки подписки учитываются в отчёте, но не добавляются в библиотеку при каждом обновлении; корректные строки импортируются как обычно.

Через API передайте `POST /proxies` JSON `{"urls": ["https://example.com/sub1", "https://example.com/sub2"], "source": "Мой список", "interval_minutes": 60}`. Ответ пакета — HTTP 200, в том числе при частичных ошибках: проверяйте `subscriptions_failed` и `results[].ok/error`.

Во вкладке **«Подписки» → «Настройки всех подписок»** задайте, например, **5 минут**, включите нужные галочки и нажмите **«Применить ко всем подпискам»**. Это изменяет все сохранённые подписки; для новых параметры задаются при импорте. Те же настройки доступны отдельно у каждой подписки. Настройки сохраняются после перезапуска. Скачивания по расписанию выполняются с параллелизмом до четырёх в пачке из десяти подписок.

- **«Удалять старые конфиги подписки при загрузке новых»** — удалять только конфиги, исчезнувшие из свежей версии. По умолчанию выключено. Неизменившиеся записи сохраняют ID, результаты проверок, blacklist и паузу повторной проверки: очередное скачивание не делает их новыми.
- **«Не удалять рабочие конфиги подписки»** — сохранять исчезнувшие, но проверенные конфиги: valid, active, leased, cooldown, duplicate, текущий постоянный прокси и конфиги в процессе проверки. По умолчанию включено; действует вместе с очисткой. Если сохранённый конфиг позже станет нерабочим, он может быть удалён при следующем обновлении. При выключенной галочке удаление исчезнувшего активного конфига закрывает его подключение.

Очистка выполняется только после непустой успешной загрузки без ошибок разбора. При частично корректном ответе новые записи импортируются, но удаление откладывается. Конфиги, принадлежащие другой подписке или импортированные вручную, сохраняются. В результате обновления показано число удалённых записей (`removed`), при ошибках разбора — `cleanup_skipped`.

**Переход со старой версии:** прежняя база не хранила связь конфига с подпиской. Такие конфиги автоматически защищены от удаления; совпадающая метка источника не доказывает принадлежность. Новые записи отслеживаются автоматически. Старые нерабочие записи можно разово удалить существующей очисткой невалидных конфигов; после повторного импорта подписки созданные записи уже будут привязаны к ней. Такая разовая очистка также сбрасывает историю неудач удалённых записей.

Для уменьшения повторных проверок настройте `fail_retry_minutes` (например, 120–360 минут) и `blacklist_after_fails` (например, 3): обновление подписки и повторная проверка нерабочего конфига имеют независимые интервалы. Частое скачивание само по себе не делает серверы рабочими. Измерение скорости лучше оставить выключенным, если требуется прежде всего проверка доступности.

API массового изменения: `PATCH /subscriptions` с JSON `{"interval_minutes": 5, "delete_old_configs": true, "keep_working_configs": true}`. Можно передать только изменяемые поля. Параметры очистки также принимают `POST /proxies` при импорте URL/списка URL и `PATCH /subscriptions/{id}`.

По умолчанию обновление добавляет новые конфиги, пропускает дубли и сохраняет существующие конфиги и аренды. Удаление подписки останавливает обновления, но не удаляет уже импортированные конфиги. Очистка библиотеки не отключает расписания подписок.

## Включение и отключение работы

Кнопки **«Включить»** и **«Отключить»** находятся над показателями в панели и доступны на любой вкладке. Отключение завершает Xray, закрывает текущие SOCKS-подключения, сбрасывает аренды и приостанавливает фоновые проверки и автоматическое обновление подписок. Панель, библиотека, настройки и ручной импорт остаются доступны. Внешние клиенты при запросе `/proxy` или `/config` получают `503 service_disabled`.

Выбор сохраняется после перезапуска приложения. После включения ядро запускается в фоне, пул собирается заново, проверки и расписания продолжают работу. Прерванные подключения нужно установить заново.

## Постоянный прокси

В **Настройках** включите **«Постоянный прокси»**, задайте SOCKS5-порт (по умолчанию `1080`) и сохраните. Этот адрес не зависит от аренды и TTL, сохраняется после перезапуска и использует общие адрес прослушивания и пароль SOCKS5. Порт должен отличаться от порта панели и диапазонов пула/проверок. Настройки постоянного прокси применяются без перезапуска.

Приложение выбирает проверенный конфиг и проверяет HTTP-соединение через постоянный SOCKS5 каждые 30 секунд (интервал настраивается). При отказе выбирается другой доступный конфиг; после сбоя ядра прокси восстанавливается на том же порту. Для работы нужен доступный проверенный конфиг: если все серверы недоступны, приложение ожидает успешных проверок и повторяет запуск. Текущий конфиг постоянного прокси исключён из выдачи обычных аренд.

Кнопка **«Сменить конфиг»** помогает, если конкретный сайт недоступен через текущий сервер: она выбирает другой проверенный конфиг, сохраняя порт и слушающий сокет. После смены повторите подключение к сайту; уже установленные соединения автоматически на другой сервер не переносятся. Ручная смена не помечает предыдущий конфиг невалидным. Если альтернативы нет, текущий конфиг сохраняется и панель сообщает об этом. В настройках показаны адрес, текущий конфиг и состояние соединения. Общая кнопка «Отключить» останавливает и постоянный прокси.

API: `POST /permanent-proxy/switch` — сменить конфиг; `GET /status` → `permanent_proxy` — адрес, готовность, текущий конфиг и последняя проверка. Параметры `PATCH /settings`: `permanent_proxy`, `permanent_port`, `permanent_check_seconds`.

## API

В панели есть вкладка **«API · документация»**: список маршрутов, параметры, схемы тела, примеры cURL и выполнение запросов с просмотром HTTP-статуса, времени, заголовков и тела ответа (JSON или текст). Работает локально без CDN. Можно использовать UI-сессию, Bearer-токен или отправить запрос без авторизации. Запросы выполняются на текущей установке и применяют реальные действия. Схема OpenAPI доступна после авторизации по `/openapi.json`.

Все служебные маршруты требуют `Authorization: Bearer <token>` либо действительную UI-сессию. `/health`, `/`, статика и `/auth/login` доступны без токена. Ошибки имеют вид `{"error":"code","message":"..."}`. Валидация возвращает 400 без раскрытия входных секретов; отсутствие прокси — 404; конфликт состояния — 409; нехватка портов/ядра — 503; превышение тела — 413.

| Метод и путь | Назначение |
|---|---|
| `POST /proxies` | Импорт `text/plain` или JSON `{data, source?}` / `{url, source?, interval_minutes?}` / `{urls: [...], source?, interval_minutes?}` |
| `GET /proxy` | Арендовать SOCKS5 |
| `GET /config` | Арендовать исходный конфиг; `lease=0` — просмотр без аренды |
| `POST /proxy/used` | Завершить аренду и отправить в отлежку: `{id}` либо `{addr}` |
| `POST /proxy/invalid` | Отметить невалидным: `{id\|addr, reason?}` |
| `POST /proxy/release` | Вернуть без отлежки: `{id\|addr}` |
| `GET /count` | Число поднятых SOCKS5; `state=active` / `leased`, `format=text` |
| `POST /service/enable`, `POST /service/disable` | Включить или отключить работу прокси; возвращает состояние приложения |
| `GET /status` | Состояния, ресурсы, очередь, скорость проверок, версия и возможности ядра |
| `DELETE /proxies?confirm=yes` | Очистка: `scope=all\|invalid\|source`, `source=...`; `all` удаляет также все подписки. Ответ: `deleted`, `subscriptions_deleted`. Настройки сохраняются |
| `GET /export/proxies` | Скачать все поднятые свободные/арендованные SOCKS5 и запущенный постоянный прокси: `format=txt` (по умолчанию) или `json`; без создания аренд, с URL-кодированными учётными данными при SOCKS-авторизации |
| `GET /export/configs` | Скачать все исходные конфиги, независимо от фильтров и пагинации: `format=txt` или `json` |
| `GET /proxies` | Пагинация и фильтры таблицы; полный исходный конфиг в `items[].link` |
| `POST /actions` | `{ids:[1,2], action:"disable\|enable\|recheck\|used\|invalid\|release"}` |
| `GET /proxies/{id}/link` | Полный исходный конфиг по явному запросу |
| `GET /proxies/{id}/history` | Последние 20 проверок |
| `GET /settings`, `PATCH /settings` | Чтение/изменение настроек; пароль меняется полем `ui_password` |
| `POST /settings/test-urls` | Проверить сохранённые URL напрямую |
| `GET /events` | Журнал: `before=<id>`, `limit=100` |
| `GET /subscriptions` | Сохранённые подписки, расписание и результаты обновлений |
| `PATCH /subscriptions` | Общие настройки всех существующих подписок: `interval_minutes`, `delete_old_configs`, `keep_working_configs` |
| `PATCH /subscriptions/{id}` | Те же настройки для одной подписки; незаданные поля сохраняются |
| `POST /subscriptions/{id}/refresh` | Обновить подписку сейчас |
| `DELETE /subscriptions?confirm=yes` | Удалить все подписки и остановить их обновления; конфиги и подключения сохраняются |
| `DELETE /subscriptions/{id}` | Удалить подписку, сохранив её конфиги |
| `GET /openapi.json` | Схема API для документации и клиентов |
| `GET /health` | Доступность HTTP-процесса (готовность xray смотрите в `/status`) |

Параметры выдачи: `geo=DE,NL`, `max_ping`, `min_speed`, `mode=best|random|random_top`, `top`, `lease_ttl`, `wait` (0–120 секунд), `format=json|text`. У `/config` дополнительно `lease=0|1`.

Фильтры таблицы: `page`, `page_size` (до 200), `state`, `reason`, `geo`, `protocol`, `source`, `q`, `min_ping`, `max_ping`, `min_speed`, `max_speed`, `raised=true`, `sort=id|ping_ms|speed_mbps|state|geo|last_check_at|source`, `direction=asc|desc`.

Пример клиента Python:

```python
import os
import httpx

api = httpx.Client(
    base_url="http://127.0.0.1:8080",
    headers={"Authorization": "Bearer " + os.environ["PROXYHUB_TOKEN"]},
    timeout=130,
)
print(api.post("/proxies", json={
    "data": "trojan://YOUR_PASSWORD@YOUR_SERVER:443?sni=YOUR_SERVER",
    "source": "my-list",
}).json())

response = api.get("/proxy", params={"geo": "DE,NL", "wait": 60})
response.raise_for_status()
lease = response.json()
try:
    # Если включён socks_auth, добавьте URL-кодированные username:password@.
    with httpx.Client(proxy="socks5://" + lease["addr"], trust_env=False) as proxy:
        print(proxy.get("https://example.com").status_code)
finally:
    api.post("/proxy/used", json={"id": lease["id"]}).raise_for_status()
```

Экспорт доступен кнопками во вкладках «Поднятые прокси» и «Все конфиги». TXT содержит исходные записи по одной на строку (для ссылок); JSON — массив исходных строк с сохранением границ записей, в том числе для смешанных Clash/sing-box/ссылок. JSON предназначен для архива и внешней обработки; прямой импорт этого массива не поддерживается. Экспорт не ограничен размером страницы и содержит ключи доступа.

Во вкладке «Подписки» есть отдельное удаление всех подписок. Полная очистка базы в настройках удаляет также подписки; уже начатые загрузки и очередь пакетного импорта не восстановят их конфиги после очистки. При очистке по источнику или невалидных конфигов подписки сохраняются.

## Данные, настройки и безопасность

- `.gitignore` исключает `_Configs/`, `data/`, `runtime/`, `exports/`, базы SQLite с WAL/SHM, журналы, резервные копии, `.env`, файлы паролей/учётных данных и приватные ключи. Экспортные файлы `proxyhub-proxies*.txt/json` и `proxyhub-configs*.txt/json` также исключены. Для собственных файлов с секретами используйте эти каталоги или добавьте отдельные правила; Git не определяет секреты по содержимому. Уже отслеживаемые файлы нужно убрать из индекса через `git rm --cached`, сохранив локальные копии. Это не удаляет данные из прошлых коммитов: если они были опубликованы, отзовите/замените ключи и отдельно очистите историю репозитория.
- База и ротируемый журнал: `data/`. Бинарник: `bin/`. Временные конфиги с правами 600 и реестр процессов: `data/runtime/`.
- `PROXYHUB_DATA_DIR` меняет каталог данных. SQLite WAL рекомендуется хранить на локальной файловой системе, не в общей сетевой папке.
- При создании **новой** БД можно задать `PROXYHUB_HOST`, `PROXYHUB_PORT`, `PROXYHUB_UI_PASSWORD`. Для внешнего web_host пароль обязателен. Позднее настройки изменяются через UI/API. Для удалённого доступа используйте доверенную сеть либо HTTPS reverse proxy.
- Настройки со знаком ↻ сохраняются сразу, но применяются после перезапуска: веб-адрес/порт, пути ресурсов, автозагрузка, bind SOCKS5, диапазоны портов и SOCKS-учётные данные. Остальные применяются к следующим операциям без перезапуска; уже начатая проверка завершает работу со своим снимком параметров.
- Сырые конфиги и ключи хранятся в БД: защищайте каталог данных и резервные копии. API-токен тоже хранится в БД, поскольку должен быть доступен владельцу. Пароль UI хранится как scrypt-хеш с солью, сравнение выполняется за постоянное время. Смена пароля отзывает текущие UI-сессии.
- API не записывает URL запросов в access-log. Сырые ошибки парсеров/xray не выводятся, поскольку могут содержать учётные данные. Настройки и полные ссылки не помещаются в журнал. Ошибки ядра диагностируются безопасными категориями, событиями и проверкой `xray run -test`.
- UI-сессии: HttpOnly, SameSite=Strict, 12 часов; проверка Origin и Fetch Metadata, защита от DNS rebinding для установки без пароля, ограничение попыток входа. Отдача статических ресурсов с CSP, без сторонних скриптов.
- Прямой выход по умолчанию блокируется в конфиге xray: отсутствие маршрута не должно привести к использованию `freedom`.
- После штатной остановки дочерние процессы завершаются. После аварии следующая загрузка сверяет PID, время создания, бинарник и путь конфига перед завершением осиротевшего процесса. Блокировка каталога не допускает двух серверов с одной БД. Запускайте один uvicorn worker.
- При восстановлении `checking → new`, `active/leased → valid`, аренды сбрасываются, пул создаётся заново. История ограничена 20 проверками на конфиг; журнал событий — 2000 записями.
- Для резервной копии остановите приложение или используйте SQLite Backup API; не копируйте только `.db` из работающей WAL-базы.

## Службы

`deploy/proxyhub.service` — пример systemd. Создайте системного пользователя `proxyhub`, установите проект в `/opt/proxyhub`, окружение Python в `.venv`, подготовьте `/var/lib/proxyhub` и разрешите пользователю запись в `/opt/proxyhub/bin`. Затем адаптируйте и установите unit. Пример задаёт `LimitNOFILE=65536` и завершение всей группы процессов.

`deploy/install-nssm.ps1` — устанавливает Windows-службу через отдельно установленный NSSM. Скрипт запускается пользователем явно в терминале администратора после первого `run.bat`. `deploy/register-task.ps1` — альтернативная задача Task Scheduler при входе текущего пользователя. Эти примеры не выполняются автоматически.

## Проверка

```powershell
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -m scripts.install_core
.venv\Scripts\python.exe -m pytest tests/test_xray_integration.py -q
.venv\Scripts\python.exe -m scripts.benchmark --count 100000
```

Интеграционные тесты используют локальные сокеты и установленный `bin/xray`; если бинарника нет, они явно пропускаются. Прокси-доступ в интернет для них не требуется. Бенчмарк пишет отдельную синтетическую БД в `.tmp/benchmark-*` и сохраняет метрики в `docs/benchmark.json`.

Проверки включают парсеры, реальные конфиги и динамический API xray, уникальность 20 конкурентных аренд, TTL/отлежку, приоритеты очереди, blacklist, дубли IP, утечку, отказ тестовых URL, гонки ручных действий, ограничение истории, авторизацию и лимиты HTTP. См. `docs/ACCEPTANCE.md` для сценариев с реальными узлами на Windows/Linux.
