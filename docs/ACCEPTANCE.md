# Проверка готовности ProxyHub

## Автоматические проверки

- `python -m pytest -q`: парсеры всех заявленных схем, битые строки, SHA256, генератор, API, состояния, планировщик и гонки.
- `python -m scripts.install_core`, затем интеграционные тесты: один настоящий процесс пула, добавление двух SOCKS5, удаление одного без перезапуска второго, отсутствие оставшихся дочерних процессов.
- `python -m scripts.benchmark --count 100000`: импорт, первая/последняя страницы, фильтрация и поиск, пиковый RSS Python. Результаты: `benchmark.json`.

Проверено при реализации: Windows x64, Python 3.13, Xray 26.10.21. Полный рабочий трафик через пользовательские VPN-серверы не проверен: рабочие конфиги не предоставлены. Linux/ARM64 и Windows 10 требуют отдельного прогона на соответствующей системе. Метрики API/памяти на синтетической базе не подтверждают предел памяти при 50 активных реальных прокси.

## Ручной чек-лист Windows 10/11 и Ubuntu 22.04

Выполнять с Python 3.11+ и реальными конфигами, на которые у оператора есть доступ.

1. Чистый запуск без `bin/` и геобазы: интерфейс доступен, xray скачивается с проверкой SHA256, MMDB открывается. При отключённом интернете UI работает, журнал содержит понятную ошибку ресурсов.
2. Импортировать образцы каждого формата, включая повреждённый конфиг и TUIC. Сверить счётчики accepted/duplicates/unsupported/parse_errors, причины и сохранённые исходники.
3. Импортировать 1000 узлов с конкурентностью 50; измерить время окончания первой проверки. Цель ТЗ — не более 15 минут; результат зависит от доступности узлов и тестовых адресов.
4. Предоставить не менее 10 валидных узлов. Проверить заполнение свободного пула до 10 за 60 секунд. Выдать часть в аренду, убедиться, что число свободных восстанавливается, а leased считаются сверх pool_size.
5. Запустить 20 параллельных GET /proxy при наличии 20 кандидатов. Все id уникальны. Повторить с `wait=30` и временно пустым пулом.
6. После used проверить закрытие TCP и UDP-порта за 2 секунды. До cooldown_until конфиг не выдаётся. TTL ведёт к тому же результату.
7. Прервать связь с арендованным сервером. При плановой проверке аренда получает broken; пул восстанавливается в течение двух минут после обнаружения отказа при наличии кандидатов.
8. Проверить два узла с одним выходным IP: один мастер, другой duplicate. Отключить/удалить мастера: второй возвращается в очередь.
9. Проверить конфиг, возвращающий прямой IP. При require_no_leak включённом он отклоняется с leak; при недоступности прямого IP счётчик неудач не растёт.
10. Включить и выключить измерения; убедиться, что выключенные пинг/скорость/гео не влияют на пороги. Для UDP проверить доступный и недоступный DNS через SOCKS5 ASSOCIATE.
11. Задать недоступные тестовые URL и проверить обработку отказа непосредственно и через всю пачку: ошибка теста, а не прирост fails.
12. Довести узел до blacklist; ручная перепроверка запускается немедленно, успешная сбрасывает fails.
13. Изменить размер пула; свободные лишние SOCKS5 закрываются, существующие аренды сохраняются. Проверить занятые порты и непересекающиеся диапазоны.
14. Установить socks_auth и перезапустить. Клиент без пароля не получает доступ, с правильными данными работает TCP и UDP.
15. Проверить фильтры, сортировку, пагинацию на 100 000 конфигов (цель <1 секунды), массовые действия, копирование полной ссылки и маскирование секретов в таблице.
16. Проверить неверный токен/пароль, cross-origin запрос, слишком большое тело, внешний web_host без пароля. Проверить повторный вход после смены пароля.
17. Остановить приложение Ctrl+C: в Task Manager/ps нет его xray. Затем проверить аварийное завершение и восстановление: очищаются только подтверждённые осиротевшие PID приложения.
18. Попробовать второй экземпляр с тем же каталогом: он отказывается запускаться и не затрагивает первый.
19. На Linux проверить права 600 на БД и временных конфигах, лимит дескрипторов, старт/стоп systemd. На Windows проверить NSSM либо Task Scheduler и отсутствие окон дочерних xray.
20. Измерить суммарную память Python + дочерних процессов при 100 000 конфигов и 50 поднятых прокси под трафиком; целевой предел — 500 МБ. Сохранить конфигурацию теста и условия нагрузки.
