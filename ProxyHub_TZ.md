# ТЗ: ProxyHub — менеджер пула прокси из VPN-конфигов

Версия 1.0 · стек: Python + xray-core · для реализации через vibe coding

## 1. Цель и границы

Утилита принимает по API большие объёмы прокси-конфигов (100 000+), проверяет их через xray-core, хранит результаты и по запросу выдаёт либо сырой конфиг, либо локальный socks5 `IP:PORT`, поднятый из подходящего конфига. Настройка и контроль — через веб-интерфейс. Работает на Windows и Linux; единственная ручная зависимость — Python.

Вне версии 1: несколько пользователей, автообновление подписок по расписанию, цепочки прокси, метрики Prometheus.

## 2. Технические решения (зафиксированы)

- Python 3.11+, FastAPI + uvicorn, asyncio, SQLite (WAL), httpx/aiohttp с поддержкой socks5 для запросов через прокси.
- xray-core — внешний бинарник. Утилита сама генерирует JSON-конфиги и управляет процессами. При первом запуске скачивает нужную сборку (Windows/Linux, x64/arm64) с GitHub Releases, проверяет SHA256 и кладёт в `./bin`. Путь к своему бинарнику можно задать в настройках. Версия и поддерживаемые протоколы определяются при старте.
- Между логикой и ядром стоит слой `CoreAdapter`, чтобы позже можно было подключить sing-box.
- Веб-интерфейс: статика (HTML + Alpine.js/htmx), без npm-сборки; все библиотеки лежат локально, интерфейс работает офлайн.
- Запуск: `python -m proxyhub` (плюс `run.bat` и `run.sh`). По умолчанию слушает `127.0.0.1:8080`. В поставке примеры службы: systemd unit и задача Windows (NSSM).
- При завершении все дочерние процессы xray гасятся; при старте убиваются «осиротевшие» процессы из pid-файла.

## 3. Допущения (проверьте — это самые спорные места)

1. **tuic не поддерживается xray-core.** Такие конфиги получают статус `unsupported` с причиной, а не пропускаются молча. hysteria2 принимается, только если установленная версия xray её умеет (проверка при старте). Если tuic критичен, нужен sing-box как второй адаптер.
2. **`pool_size` — число свободных поднятых socks5** (состояние `active`). Выданные (`leased`) считаются сверх этого числа. Жёсткий предел — размер диапазона портов.
3. **Аренда заканчивается** по истечении TTL либо по явному `used` от клиента. В обоих случаях прокси уходит в `cooldown`.
4. **Утечка IP** = выходной IP через прокси совпадает с прямым IP машины (прямой IP определяется при старте и раз в час).
5. **Гео** — страна (ISO-2) по реальному выходному IP, определённому через прокси. База — локальная mmdb (DB-IP Country Lite, скачивается автоматически; путь можно задать вручную).
6. **Дедуп по выходному IP:** побеждает первый прошедший проверку, остальные получают `duplicate` со ссылкой на мастера. Если мастер стал невалидным или удалён, дубли возвращаются в очередь проверки.
7. **Единицы:** скорость в Мбит/с, пинг в мс.

## 4. Состояния прокси

| Состояние | Смысл |
|---|---|
| `new` | принят, ещё не проверялся |
| `checking` | идёт проверка |
| `valid` | прошёл проверку и пороги, socks5 не поднят |
| `active` | valid + поднят socks5, свободен |
| `leased` | выдан клиенту, есть `lease_expires_at` |
| `cooldown` | использован, лежит в отлежке до `cooldown_until`, socks5 закрыт |
| `invalid` | проверка не пройдена; поле `reason`: connect_fail, timeout, ping_high, speed_low, geo_mismatch, leak, udp_fail, manual |
| `duplicate` | тот же выходной IP, что у другого прокси (`master_id`) |
| `blacklisted` | N неудач подряд, автоматически не проверяется |
| `disabled` | отключён вручную, не проверяется и не выдаётся |
| `unsupported` | протокол или транспорт не поддерживается ядром (`reason`) |
| `parse_error` | не удалось разобрать; хранится сырая строка и причина |

Переходы:

- `new → checking → valid | invalid | duplicate`
- `valid → active` (пулу нужны прокси); `active → valid` (socks5 закрыт, например уменьшили `pool_size`)
- `active → leased` (GET /proxy или /config); `leased → cooldown` (TTL или used)
- `cooldown → checking → valid` по `cooldown_until` (перепроверка после отлежки включена по умолчанию, `recheck_after_cooldown`)
- любое → `disabled` вручную; `disabled → new` при включении
- `invalid → checking` по таймингам; N неудач подряд → `blacklisted`
- ручная перепроверка обходит все таймеры и blacklist; успешная проверка сбрасывает счётчик неудач.

## 5. Приём и разбор конфигов

- Форматы: ссылки `vless://`, `vmess://`, `ss://`, `trojan://`, `hysteria2://` (`hy2://`), `tuic://` по одной на строку; подписка (base64-список или обычный список); Clash YAML (`proxies:`); sing-box JSON (`outbounds`). Формат определяется автоматически. Можно передать URL подписки, тогда утилита скачивает её сама.
- Каждый конфиг приводится к внутренней нормализованной модели. Дедуп конфигов по хешу: протокол, хост, порт, uuid или пароль, параметры транспорта; имя (remark) игнорируется.
- Метка источника `source` необязательна.
- Каждая строка получает исход: `accepted`, `duplicate_config`, `unsupported` (с причиной) или `parse_error` (с причиной). Неразобранные и неподдерживаемые сохраняются в базе и видны в интерфейсе по фильтру статуса.
- Приём 100 000 строк быстрый: API отвечает счётчиками, проверки уходят в очередь.
- Лимит размера тела запроса настраивается (по умолчанию 50 МБ).

## 6. Проверка качества

Два этапа: сначала дешёвый, потом дорогой, чтобы не тратить трафик на заведомо плохие прокси.

**Запуск.** Конфиги проверяются пачками: один процесс xray на `check_batch_size` конфигов (по умолчанию 25), для каждого свой временный socks-inbound из `check_port_range`, маршрутизация inbound → outbound по тегам. Одновременно проверяется не более `check_concurrency` конфигов.

**Этап 1 (дешёвый):**

1. Запрос на ping-URL через прокси (ожидается 2xx/204). Первый запрос — прогрев, затем `ping_samples` замеров (по умолчанию 3); пинг = медиана. Если URL недоступен, берётся следующий из списка.
2. Если включены гео, проверка утечки или дедуп: запрос на IP-echo URL через прокси даёт выходной IP.
3. Гео: страна по mmdb. Утечка (если включена): выходной IP равен прямому IP машины → `invalid(leak)`.
4. Опционально UDP-проверка (`check_udp`): DNS-запрос через socks5 UDP ASSOCIATE. При `require_udp` провал = invalid.
5. Пороги: `ping ≤ max_ping`, страна в разрешённых (или «любое»).
6. Дедуп по выходному IP.

**Этап 2 (дорогой)** — только если этап 1 пройден и замер скорости включён: скачивание с speed-URL не более `speed_max_mb` или `speed_timeout` секунд; скорость = байты / время (средняя). Если URL недоступен, берётся следующий. Порог `speed ≥ min_speed`.

**Правила галочек.** Выключенный замер не выполняется, а его критерий игнорируется. Базовое условие всегда: через прокси получен успешный HTTP-ответ. Результаты замеров пишутся в базу, даже если прокси признан невалидным (с причиной).

**Fallback-списки URL** (ping, speed, IP-echo) настраиваются. Если тестовый адрес недоступен ни через один прокси пачки, а напрямую тоже недоступен, это ошибка теста, а не прокси: счётчик неудач не растёт, в журнал пишется событие.

## 7. Пул и выдача

- **Поддержание пула.** Фоновая задача держит `pool_size` свободных socks5. Кандидаты — `valid`-прокси, выбранные по режиму: `best`, `random_top` (случайный из `top_x` лучших) или `geo` (только заданные страны, затем best). «Лучший» определяется параметром `best_sort`: `balanced` (по умолчанию: speed / (1 + ping/100)), `speed` или `ping`.
- **Поднятие.** Один «пул-xray» процесс; inbound, outbound и правила добавляются и удаляются на лету через gRPC API xray (HandlerService/RoutingService) без перезапуска остальных. Запасной режим на случай проблем с API: перегенерация конфига и перезапуск пула (флаг в настройках). Порт берётся из `pool_port_range`; bind по умолчанию `127.0.0.1`; опционально логин/пароль на socks5; UDP включён.
- **GET /proxy** берёт подходящий `active` по фильтрам и режиму, помечает `leased` с `lease_expires_at = now + lease_ttl` и возвращает адрес. Выдача атомарна: один прокси не может уйти двум клиентам. Если подходящего `active` нет, но есть `valid` (`on_demand`, по умолчанию включено), прокси поднимается на лету; иначе `404 no_proxy_available` (параметр `wait=N` позволяет подождать до N секунд).
- **GET /config** работает так же, но возвращает исходную ссылку без поднятия socks5. Такая выдача тоже ведёт к `leased → cooldown`; параметр `lease=0` позволяет просто посмотреть без аренды.
- **Конец аренды:** по `used` от клиента или по TTL socks5 закрывается, порт освобождается, прокси уходит в `cooldown` на `cooldown_minutes`, пул дозаполняется.
- **Прокси умер во время работы** (плановая перепроверка активного не прошла): socks5 закрывается, прокси → `invalid`, аренда прерывается с пометкой `broken`, пул дозаполняется.

## 8. Планировщик и тайминги

Очередь проверок с приоритетами (выше — раньше):

1. Ручные перепроверки.
2. Плановая перепроверка `active` и `leased` (раз в `recheck_active_minutes`).
3. Новые (`new`).
4. Плановая перепроверка `valid` (раз в `recheck_valid_minutes`).
5. `invalid`, у которых прошла пауза после неудачи.

Правила:

- После неудачной проверки прокси не проверяется `fail_retry_minutes` (поле `next_check_at`).
- Если неудач подряд ≥ `blacklist_after_fails`, прокси → `blacklisted` и автоматически не проверяется никогда (0 = отключено).
- Любая успешная проверка сбрасывает счётчик неудач.
- Если пул не заполнен, приоритет у кандидатов, которые с большей вероятностью валидны (недавно проверенные `valid`).
- При 100 000+ конфигов очередь выбирается SQL-запросом по индексу `next_check_at`, а не загрузкой всех строк в память.

## 10. API

Общее: JSON; авторизация `Authorization: Bearer <token>` (токен генерируется при первом запуске и виден в интерфейсе); ошибки в виде `{"error": "code", "message": "..."}`. Прокси идентифицируется по `id` или по `addr` (`ip:port` поднятого socks5). Коды: 200, 400, 401, 404 (`no_proxy_available`), 409, 503 (нет свободных портов).

**GET /proxy** — выдать поднятый socks5 в аренду.

- Параметры: `geo` (ISO-2 через запятую), `max_ping`, `min_speed`, `mode` (best | random | random_top), `top`, `lease_ttl`, `wait` (секунд), `format` (json | text).
- Ответ json: `id`, `addr` (например `127.0.0.1:10801`), `host`, `port`, `username`, `password`, `geo`, `exit_ip`, `ping_ms`, `speed_mbps`, `udp`, `lease_expires_at`. При `format=text` — просто `127.0.0.1:10801`.

**GET /config** — выдать исходный конфиг без поднятия socks5.

- Те же фильтры и режимы, плюс `lease=0|1` (по умолчанию 1).
- Ответ: `id`, `link`, `protocol`, `geo`, `ping_ms`, `speed_mbps`, `lease_expires_at`. При `format=text` — ссылка.

**POST /proxy/used** — тело `{id | addr}`. Прокси → `cooldown`, socks5 закрывается.

**POST /proxy/invalid** — тело `{id | addr, reason?}`. Прокси → `invalid` так же, как при неудачной проверке (счётчик неудач растёт, socks5 закрывается, пул дозаполняется).

**POST /proxies** — добавить конфиги. Тело: `text/plain` (ссылки, подписка, YAML или JSON) либо JSON `{data | url, source?}`. Ответ: `received`, `accepted`, `duplicates`, `unsupported`, `parse_errors`, `errors` (первые 100 с номером строки и причиной).

**DELETE /proxies** — очистить базу. Обязателен `?confirm=yes`; необязательно `scope=all|invalid|source` и `source=`. Все поднятые socks5 закрываются.

**GET /status** — подробная информация: версия утилиты, uptime, версия xray и его возможности, счётчики по каждому состоянию, число поднятых / свободных / выданных, размер очереди проверок, скорость проверок в минуту, занятость портов, текущие настройки пула, прямой IP машины, последние ошибки.

**GET /count** — число поднятых socks5 (`active` + `leased`); `?state=active` — только свободные. Ответ `{"count": N}`, при `format=text` — число.

Опционально: `POST /proxy/release` (вернуть в пул без отлежки) и `GET /health`.

## 11. Веб-интерфейс

- Вход по паролю. По умолчанию слушает только localhost; при другом bind-адресе пароль обязателен.
- **Дашборд:** счётчики по состояниям, поднято / свободно / выдано, очередь проверок, скорость проверок, прямой IP, статус xray.
- **Поднятые прокси** (главный экран): `addr`, протокол, гео (с флагом), пинг, скорость, UDP, состояние, время до конца аренды или отлежки, последняя проверка, источник. Действия на строке и массово (чекбоксы): отключить, отметить невалидным, отметить использованным, перепроверить, копировать `ip:port`. Автообновление раз в 3 секунды (SSE или polling).
- **Все конфиги:** серверная пагинация (100 000+), фильтры (состояние, причина, гео, протокол, источник, диапазоны пинга и скорости), сортировка, поиск. Те же действия плюс «включить». В ссылках секреты маскируются, полная ссылка копируется кнопкой.
- **Добавление:** текстовое поле, загрузка файла или URL подписки, поле источника, результат разбора с причинами ошибок.
- **Настройки:** все параметры из п. 9 с валидацией; кнопка «проверить URL»; кнопка «очистить базу» с подтверждением.
- **Журнал событий:** ошибки xray, смены состояний, ошибки теста.
- Язык интерфейса: русский; строки вынесены в словарь.

## 12. Нефункциональные требования

- Память: не более 500 МБ при 100 000 конфигов и 50 поднятых прокси.
- БД: индексы по `state`, `next_check_at`, `geo`, `ping`, `speed`, `hash`, `exit_ip`; режим WAL; история проверок — последние 20 записей на конфиг.
- Восстановление после перезапуска: `checking` → `new`; все аренды сбрасываются, прокси из `leased` и `active` → `valid` (socks5 всё равно закрыты); пул заполняется заново.
- Безопасность: по умолчанию localhost; токен API и пароль UI (сравнение за постоянное время); ключи и ссылки конфигов не пишутся в логи; файл БД с правами 600 на Linux.
- Windows: xray запускается без консольного окна, процессы завершаются вместе с деревом; в README предупреждение об антивирусе. Linux: проверка лимита файловых дескрипторов при старте.
- Логи с ротацией и уровнями.
- Тесты (pytest): парсеры (образцы каждого протокола и битые строки), генератор xray-конфигов, машина состояний, планировщик с замоканным ядром. Ручной чек-лист для Windows и Linux.

Этапы (после каждого приложение запускается, тесты проходят; к следующему не переходить, пока не готов предыдущий):

2. Ядро: установщик xray, генератор конфигов, проверка одного конфига (этап 1).
3. Пакетная проверка, планировщик, тайминги, blacklist, гео, утечка, дедуп, скорость, UDP.
4. Пул: поднятие socks5, `GET /proxy`, `GET /config`, аренда, отлежка, `used` и `invalid`, `/status`, `/count`.
5. Веб-интерфейс.
6. Упаковка: README, примеры службы, `run.bat` и `run.sh`, финальные тесты.

## 14. Критерии приёмки

- Все протоколы из п. 5 разобраны на тестовом наборе; неразобранные и неподдерживаемые строки получили статус и причину.
- 1000 конфигов при `check_concurrency=50` проверяются не дольше 15 минут.
- Пул из 10 прокси поднимается за 60 секунд при наличии валидных; после смерти прокси восстанавливается за 2 минуты.
- 20 параллельных `GET /proxy` не выдают один прокси дважды.
- После `used` порт освобождается за 2 секунды, прокси не выдаётся до конца отлежки.
- Ручная перепроверка снимает blacklist и обходит паузу после неудачи.
- Дедуп по выходному IP работает: два конфига с одним выходным IP дают один `valid` и один `duplicate`.
- Включённая проверка утечки отбраковывает прокси, выходной IP которого равен прямому.
- Запуск и остановка корректны на Windows 10/11 и Ubuntu 22.04; после остановки не остаётся процессов xray.
- При 100 000 конфигов страница «Все конфиги» отвечает не дольше секунды.
